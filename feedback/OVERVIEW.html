feedback · 数据合成模块

从模型的错题里学习,定向制造高质量训练数据

不是凭空造题,而是先看模型在哪里栽了跟头,然后专门生产同类型的难题。这个模块的目标是把"造数据"从盲打变成有的放矢。

为什么要做这件事

训练一个 ToM(心智理论)模型,你需要大量高质量的训练数据。直接让一个大模型"随便造一万道题",看起来高效,但实际效果往往很差 —— 造出来的题大多是模型已经会的,真正能让它进步的难题反而没几道。

❌ 随机生成的问题

不知道模型现在哪里弱,生成出来的题大多重复模型已经擅长的能力。算力花了,模型却几乎没提升。

✓ 这个模块的思路

先用 ToMEval 跑出模型的错题清单,分析它在哪些能力维度上集中翻车,然后只针对这些薄弱维度合成新题。

这个思路在教育界已经被验证过 —— 错题本是最高效的学习材料。模型学习也一样:已经做对的题,再做一万遍也没用;反复练那些做错的题,才会真正提高。

设计理念:像人类老师备课一样工作

想象一位老师在期中考试后给学生出补强练习。一个粗糙的做法是:把所有错题原样复印一份让学生再做一遍。但好老师不会这样 —— 她会先 看一摞错题归纳出共性:"这一批学生在‘逆否命题’上集中翻车","那一批是‘函数定义域’没掌握"。然后她针对这些共性,出新的、不同情境的题目,让学生在同一个能力点上反复练习。

feedback 用的就是这个备课思路。从找错题、归纳病因,到出新题、去重过滤,每一步都对应老师备课的一个动作。

核心思路

整个流程就是把"老师备课"自动化:

  • 第一步:翻错题本。 从 ToMEval 的评估结果里,把模型们做错的题挑出来。
  • 第二步:找共性。 把同一能力维度的错题打包给强模型,让它归纳"这批错题反映出什么能力短板"。
  • 第三步:对症出题。 按归纳出的诊断报告,生成新的同类型难题。
  • 第四步:去重把关。 防止合成的题和测试集太像、合成题之间互相重复。

整体流程一览

从 ToMEval 的评估结果到一份干净的训练数据,要经过这四个阶段:

ToMEval 评估结果(prediction.jsonl)
1
挑错题
从多个模型的评估结果中,找出它们都答错的题 → 这些是高价值目标

四个阶段在做什么

1
挑错题:从评估结果中找"高价值目标"
同一道题,如果只有一个模型答错,可能是这个模型本身的瑕疵;但如果好几个模型都答错,那大概率是这道题代表的能力是当前模型们的共同短板。
所以这一步做两件事:
  • 多模型并集:任意一个模型答错就纳入候选。
  • 标重点:有两个或更多模型同时答错的题,会被打上"hard"标记 —— 它们是后续合成时最重要的参考样本。
每条错题还会带上它来自哪个能力维度(比如"错误信念"、"视角转换"),这是阶段二分组归纳的依据。
关键产出:一份带维度标注的错题清单
2
按维度归纳病因:让强模型当"教研组长"
最朴素的合成做法是:对每条错题单独生成一道改写题。但这样合成出来的题往往只是"换皮"原题,缺乏新鲜感,而且模型可能只是把同一个错误又犯了一遍。
这里改用 批量归纳的思路:把同一能力维度下的 K 条错题打包丢给强模型,问它一个问题:这批错题反映出模型在这个维度上有什么共同的弱点?应该从哪些角度补强?
强模型会输出一份结构化的"诊断报告",大致长这样:
能力维度:错误信念
共性错误模式:模型在事件未被目击时,没能正确更新角色的信念
核心认知操作:信念状态更新
建议合成主题:图书馆场景、惊喜派对、隔间换位…
难度分布建议:简单 20% / 中等 50% / 困难 30%
这一步把零散的错题提炼成 可复用的"出题指令",是整个模块最关键的智力步骤。
关键产出:每个维度一份诊断报告
3
按报告造新题:让强模型"对症出题"
读取阶段二的诊断报告,按报告里的建议主题、难度比例去生成新题。
这一步有两个值得注意的设计:
  • 按目标量分配:想合成多少题、每份报告产出多少题,这两个数字决定了用多少份诊断报告;同时按各维度的错误占比,分配每个维度的合成量 —— 错得多的维度补得多。
  • 严格遵守原数据集格式:每个数据集有自己的格式约定(ToMBench 是 4 选 1、BigToM 是 2 选 1、SocialIQA 是 3 选 1),合成时按数据集的 schema 约束输出,避免格式错位。
关键产出:候选合成题(还未去重)
4
去重过滤:LSH 守门员
合成的数据要进训练集之前,必须做两轮去重:
  • 和测试集去重:把合成题和测试集逐条比相似度,过于相似的丢掉。这一步极其重要 —— 如果合成题和测试集"长得很像",训练后模型在测试集上的高分就是假的(数据泄漏)。
  • 合成题之间去重:防止两份诊断报告生成出非常像的两道题,浪费训练资源。
具体用的是 MinHash LSH(局部敏感哈希)算法 —— 一种快速找出"长得很像的文本"的标准技术。它不需要 LLM,纯算法就能跑,速度快、效果稳定。
关键产出:synthetic.parquet,可以交给 filter 评估了

每个阶段用什么模型,为什么

阶段用什么为什么
阶段一 挑错题 不需要模型 只是从 ToMEval 现成的 prediction.jsonl 里筛错题,纯文件操作。
阶段二 归纳病因 强模型 跨样本归纳抽象能力是核心,弱模型容易就事论事说不到点子上。
阶段三 合成新题 强模型 合成质量直接决定训练效果,这一步省钱省错地方。
阶段四 去重 不需要模型 MinHash LSH 是确定性算法,效果稳、速度快、零调用成本。

支持哪些数据集

每个数据集有自己定义"能力维度"的字段(用来给阶段二做归纳分组),目前已支持的有:

ToMBench
维度:错误信念、视角转换、失态识别…
BigToM
维度:真信念 / 错误信念
SocialIQA
维度:want / need / react / effect
EmoBench
维度:情绪归因相关
FanToM
维度:信念追踪相关
HiToM
维度:信念阶数(一阶 / 二阶)

想接入新数据集,只要补上"哪个字段是能力维度"以及"输出的 schema 长什么样"就行。

这个模块在数据飞轮中的位置

feedback 是 ToMEval 数据飞轮的上半场,职责是"造";下半场是 filter,职责是"检"。两者明确分工,互不重叠:

feedback(本模块) 从模型错题中
合成定向训练数据
→
filter 给合成数据做体检,
留下能用的、修可以修的

中间通过 synthetic.parquet 这个文件衔接。本模块只管"造得好",不管"造得够不够难" —— 难度验证在 filter 里完成。

为什么要这样拆?早期版本里"造"和"检"放在同一个模块,结果就是修复逻辑、难度验证、合成主体逻辑混在一起,谁也改不动。拆开之后,每个模块只关心一件事,迭代起来轻得多。

怎么用起来

# 完整跑一遍:挑错题 → 归纳 → 合成 → 去重 python run_feedback.py --stage all --dataset ToMBench # 也可以单跑某一阶段(比如想重新调阶段三的合成 prompt) python run_feedback.py --stage load --dataset BigToM --max-bad-cases 80 python run_feedback.py --stage diagnose --dataset BigToM python run_feedback.py --stage synth python run_feedback.py --stage dedupe

运行完成后,产出会落在 data_output/ 目录下,最终交付物是 data_output/synth_clean/<数据集>/synthetic.parquet,直接喂给 filter 做下一步质量评估。

想了解每个阶段的实现细节?可以看 feedback/README.md 和 docs/data_flywheel_v3.md。
