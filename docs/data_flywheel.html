BACKGROUND03 / 16
01研究背景
Data quality over volume
01

数据规模不等于训练价值

ToM 训练数据的关键不是“更多”，而是“更贴近模型短板、更少噪声、更需要真实推理”。数据价值来自模型短板对齐和严格质量准入。

从数量增长转向质量闭环。
PROBLEM04 / 16
01问题定义
Random generation is insufficient

随机合成缺少可追踪的改进路径

随机合成的局限

不知道模型真正弱在哪个能力维度。
新增样本可能只是已有模式的重复变体。
简单题、坏题、捷径题会混入训练池。

闭环必须回答的四个问题

模型错在哪里：Evaluate 产生可定位信号。
下一轮补什么：Feedback 形成生成计划。
候选是否合格：Filter 决定保留或修复。
训练是否有效：Train 后回到评测验证。
评测不是终点，而是下一轮数据生成的起点。
FRAMEWORK05 / 16
02整体框架
Closed-loop data engineering

四模块数据飞轮：Eval → Feedback → Filter → Train

Evaluate把模型输出转成分数、错误样本和能力缺口。
Feedback + Filter一个决定补什么，一个决定什么样本能进训练。
Train用版本化训练和回归评测验证数据是否真的有效。
闭环结构比单向流水线更关键。
MODULES06 / 16
02四模块协同
Input, process, output

每一环都要产出下一环可消费的工程对象

EVALUATE模型与基准集批量推理、计算指标、聚合 bad cases，输出 scores / failed samples / error tags。
FEEDBACK错误到生成计划按能力维度归因，生成目标能力、题型、难度和约束，输出候选样本池。
FILTER候选到训练准入检查难度、可答性和捷径风险，输出 keep / repair / drop 的分流结果。
TRAIN数据到模型版本版本化入池、混合采样训练、回归评测，输出新模型和下一轮弱点。
数据飞轮的关键是接口清楚，而不是只画循环箭头。
EVALUATE07 / 16
03Evaluate 模块
Evaluation to feedback signals

评测产生可用于数据生成的反馈信号

1

选择模型与数据集

固定模型版本、任务配置和评测 split，保证每轮结果可复现。

2

批量推理

记录模型答案、置信表达、拒答和格式错误，保留原始输出。

3

指标计算

按任务计算 accuracy、pass/fail、维度分数和模型间差异。

4

错误收集

聚合 failed samples，形成 bad case pool 进入诊断。

输出对象score table、failed samples、per-model weakness profile、可追踪实验目录。
Evaluate 不只是打分，而是为 Feedback 提供结构化信号。
EVALUATE08 / 16
03错误诊断
Bad cases to capability gaps

从错误样本到能力缺口

错误类型

belief tracking无法持续追踪角色信念状态。
false belief混淆真实世界与角色所知信息。
multi-agent reasoning多角色嵌套意图推理失败。

错误强度

single-model fail单个模型失败，用于模型画像。
multi-model fail多个模型失败，说明是稳定短板。
strong-model fail强模型也失败，优先检查题目质量。

生成价值

低优先级偶发格式问题或标签噪声。
可用于反馈错误稳定且能力归因清楚。
高价值补强多模型失败、可解释、可扩展成新题型。
只有可归因的错误，才适合作为下一轮生成方向。
FEEDBACK09 / 16
04Feedback 模块
Error patterns to generation plans
04

从错误中提炼生成方向

Feedback 的输入是 bad cases、错误标签、能力缺口和数据集 schema；输出不是单条改写，而是 generation instruction、target capability、constraints 和 candidate samples。

模型错误到能力诊断，再到定向合成。
FEEDBACK10 / 16
04方法链路
Bad cases to candidates

Feedback 流程：诊断、规划、生成、去重

1

错误聚合

按任务、能力维度和模型失败模式聚合 bad cases，避免被单条异常样本带偏。

2

能力归因

判断失败来自 ToM 推理、语境理解、标签歧义还是输出格式问题。

3

生成计划

明确需要补强的能力、题型、上下文结构、难度区间和禁止泄漏信息。

4

候选合成

生成同能力、不同表面的新样本，并保留生成来源和目标能力标签。

从“逐条改写”升级为“按能力维度生成”。
FEEDBACK11 / 16
04生成质量控制
De-duplication and contamination control

候选数据进入 Filter 前先控制重复和污染

相似度控制

检查候选样本与原测试样本、训练样本的语义和结构相似度。

  • 降低测试集污染风险
  • 避免直接改写原题
  • 保留能力相似但表面不同

模板重复控制

统计角色、事件、问法和答案位置分布，避免生成池被少数模板主导。

  • 控制题型多样性
  • 控制角色和场景重复
  • 避免答案模式偏置

标签泄漏控制

检查题面是否直接暴露答案，或通过表面关键词让模型绕过 ToM 推理。

  • 移除提示性措辞
  • 检查选项泄漏
  • 标记高风险样本
输出为 candidate pool，交给 Filter 做训练准入裁决。
FILTER12 / 16
05Filter 模块
Quality gate for generated data
05

从候选数据中筛出训练价值

Filter 的输入是 candidate pool；核心判断是难度、可答性和捷径风险；输出是 keep、repair、drop 三类去向，决定样本是否能进入训练闭环。

候选样本到质量裁决，再到训练池。
FILTER13 / 16
05质量判断
Difficulty, answerability, shortcut

Filter 流程：难度、可答性、捷径检测

难度判断

用弱模型 pass@k 或多模型通过率判断 easy / medium / hard。

  • easy：训练增益低，优先修复或降权
  • medium：可作为稳定训练样本
  • hard：高价值补强样本

可答性判断

用强模型和规则检查题目是否自洽、标签是否一致、信息是否充分。

  • 排除逻辑矛盾
  • 排除标签错误
  • 标记轻微歧义进入 repair

捷径判断

遮蔽关键上下文后重测，如果仍能答对，说明样本可能不需要真正推理。

  • 检查关键词泄漏
  • 检查选项偏置
  • 检查背景常识直答
三类判断共同决定样本是否能进入训练。
DECISION14 / 16
05过滤决策
Keep, repair, drop

决策树：保留、修复、丢弃

保留hard / medium、可答、无明显捷径，进入训练池。
修复有价值但难度不足、轻微歧义或上下文不完整，回到候选池重检。
丢弃不可答、标签冲突、污染风险高或多轮修复失败。
Filter 的核心是按结果分流，而不是全量串行评估。
TRAIN15 / 16
06Train 模块
Data to model version

高质量样本反哺模型，并回归评测验证

1

数据入池

接收 keep 样本和 repair 后重新通过的样本，记录来源、目标能力和过滤结果。

2

混合采样

与原有训练数据按能力维度和难度比例混合，避免新数据覆盖旧能力。

3

训练更新

形成新的训练版本和模型版本，保留数据版本与模型版本映射。

4

回归评测

重新跑 ToMEval，比较目标能力提升和非目标能力退化。

5

下一轮弱点

把新的 failed samples 回传 Evaluate/Feedback，启动下一轮飞轮。

Train 的输出不是终点，而是下一轮 Eval 的输入。
RESULT16 / 16
END结果总结
Data and model co-evolution

让数据和模型一起迭代

Eval 更准知道模型错在哪里，避免盲目造数。
Feedback 更准知道下一轮该补什么能力和题型。
Filter 更净知道什么样本值得进入训练池。
Train 更稳知道训练是否真的带来能力提升。

Eval 暴露问题，Feedback 定义补强方向，Filter 控制数据质量，Train 验证数据价值。

不是更多数据，而是更有效的数据。End
