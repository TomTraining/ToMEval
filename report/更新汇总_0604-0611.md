# ToMEval 更新汇总(2026-06-04 ~ 06-11)

> 按功能模块归类,只讲功能层面的增 / 删 / 改,不涉及具体实现代码。

---

## 一、评测协议体系(全新核心能力)

### 新增
- **四种评测协议**,采样参数、system prompt 风格、答案提取器三者统一由协议驱动:
  - `direct`:temp=0,不思考,1 次采样,"裸答"(直接输出 `\boxed{}`,不解释),取第一个 `\boxed{}`。
  - `direct_think`:temp=0.6,开思考,1 次,裸答风格。
  - `cot`:temp=0.6,开思考,1 次,"step by step"逐步推理,最终答案放最后一行 `\boxed{}`,取最后一个。
  - `del_tom`:temp=0.6,开思考,**同一题跑 8 次 + 多数投票**,且不打乱选项顺序。
- **del_tom 多数投票聚合**:
  - 单选 → 8 次结果取出现最多的字母(平局取字母序最小)。
  - 多选 → 逐字母严格多数(某字母出现在过半 repeat 才计入)。
  - 开放题 → 文本投票不可靠,退化为取代表样本做一次 LLM judge。
  - 判分时把同一题的多次采样折叠成「每题一条」,但 total 仍按真实题数计。
- 协议为纯函数模块,采样参数集中成一张权威表,便于复现与消融。

### 修改
- **答题格式指令从 user prompt 移到 system prompt**,user 侧只留题目内容。
- `ContentClient` 支持按调用传入不同 system prompt。
- 选项 shuffle 可关闭(del_tom 必须关,否则按字母投票无意义)。
- 答案提取器按协议分派(direct / cot / legacy)。
- 开放题判定收紧为「无 wrong 选项且唯一 correct」。
- `experiment_config.yaml` 的 `llm` 段精简为**只剩连接参数**,采样 / repeats 全交给协议。
- 入口 `run_all.py` → `run_eval.py`,`stage`(predict/metric/visualize/all)与 `datasets` 列表移入 `experiment_config.yaml`。

### 删除
- 移除标准参数强校验模块(见文末「曾短暂存在」)。

## 二、开放题判分(open_judge,全新可插拔体系)

### 新增
- **三种判分模式**,按各数据集 `config.yaml` 的 `open_judge` 字段选择:
  - `f1`:无需 judge model,token/char 级 F1 对比标准答案 + 阈值二值化(适合短答案)。
  - `llm_simple`:单 judge 二元判定(参照式对比,输出 is_correct),为默认值,保持历史行为。
  - `rubric`:数据集自带 rubric prompt 打总分,可双 judge 取平均,过阈值算对(适合社会认知长答案)。
- 上下文 `OpenJudgeContext` 一次性构建并集中校验,judge / voting / pipeline 三处统一只认这个上下文。
- f1 与 rubric 各用独立阈值 key(`f1_threshold` / `open_threshold`),量纲不混用。

### 修改
- **judge 配置从全局下放到各数据集 `config.yaml`**(判分方式被视为数据集答案格式的内在属性);保存结果时对 judge 配置脱敏。

## 三、可视化模块(src/visualization,全新)

### 新增
- **数据集无关的自动出图**,只消费 `metrics.json`,任意数据集通用:
  - 每个 `by_<x>` 分组 → 一张准确率柱状图(带样本数标注)。
  - 组合键(如 V4p2 的「维度×题型」)→ 自动透视成热力图。
  - 含 judge 打分时 → judge 一致性图(散点 + Bland-Altman),否则跳过。
  - 多个 `metrics.json` → 额外出多模型对比图 + 雷达图。
  - 自动挑选支持中文的字体,挑不到则回退默认不报错。
- **评测 stage 新增 `visualize` 选项**;`all` 从「预测 + 判分」升级为「预测 + 判分 + 出图」一条龙。
- 提供独立 CLI:`python -m src.visualization --results <目录...> --out <dir>`。
- 新增 `docs/visualization.md`。

## 四、数据筛选流水线(filter)

### 新增
- **四个阶段独立开关**,可单独开关以做消融 / 省 API 成本,关闭时优雅降级:
  - `passk_enabled=false`:跳过难度分桶,所有样本按 partial 走可回答性/shortcut(失去 easy/hard)。
  - `answerability_enabled=false`:假设全部可回答,全失败样本归 hard 而非 bad。
  - `shortcut_enabled=false`:假设全部非 shortcut,partial 样本归 medium。
  - `repair_enabled=false`:只跑单轮评估打标,不修复 / 不迭代 / 不标 unfixable。
- **pass_k 与 shortcut_k 独立配置**(各自缺省回退 3)。
- **bad 原因细分统计**:按可回答性细分 bad 的成因,流入 `filter_summary.json` 并在汇总报告中展示。

### 修改
- `filter/run_filter.py` → `filter/pipeline.py`,清理入口文件。

## 五、多语言支持(评测 / filter / feedback 三链路)

### 新增
- **统一语言归一化**:新增 `lang.py`,从 `meta.lang/language` 统一识别样本语言。
- 恢复 ToMBench / EmoBench 的中文评测数据,三条链路均按样本语言切换内容文案:
  - 评测:中文 QA 模板 + 中文 `\boxed` 指令;judge 中文措辞分支。
  - filter:shortcut 中文占位符/指令、可回答性中文指令、repair 按语言生成内容。
  - feedback:维度按语言拆分(`__zh` 后缀);诊断报告记录语言;合成时按语言参数化,中文报告合成中文题并写回语言标记。
- **关键设计**:结构协议(A-Z 字母、`\boxed{}`、JSON key、answerability 英文枚举)保持语言无关,只切换自然语言内容。

### 修改
- `<think>` 标签剥离:开思考时把混在正文里的 `<think>...</think>` 自动分离为 reasoning,兼容成对 / 仅闭合 / 被截断三种形态。
