filter · 数据质量评估模块

给合成训练数据做"体检"的流水线

合成数据看起来都长得差不多,但训练价值千差万别。这个模块的工作就是 —— 在数据进入训练之前,自动识别哪些样本是宝、哪些是渣,把渣修好或者扔掉。

为什么要做这件事

用大模型合成训练数据已经成了主流做法。但合成出来的题目,直接拿去训练往往会让模型变得"会猜不会想"。原因是合成数据天然带着三类毛病:

毛病一
太简单
小模型不需要思考就能答对。这种题训练时白白消耗算力,模型学不到新东西。
毛病二
藏着捷径
不看故事、不看问题,光看选项就能猜出来。模型学到的是"怎么钻空子",不是"怎么推理"。
毛病三
题目本身有问题
前提矛盾、答案歧义、逻辑不自洽。这种题进了训练集就是噪声,把模型带歪。

一个好的训练样本应该是:题目本身成立 → 不能靠捷径答对 → 难度对模型有挑战。filter 就是按这三条标准,给每条样本"过堂"。

设计理念:像医院分诊台一样工作

想象一家医院的急诊室。如果对每个病人都做全套检查 —— CT、抽血、心电图全上 —— 既慢又贵。聪明的做法是 按症状分流:先量个体温,体温正常的病人直接走绿色通道;体温异常的再做下一步检查。

filter 用的就是这个思路。我们 不对每条样本做全量检查,而是先做一个最便宜的初筛,根据初筛结果把样本分到不同的"诊室",每条样本只走自己该走的那条路径。这样在保证覆盖度的前提下,大幅省掉了不必要的强模型调用。

核心思路

把质量评估拆成 四个阶段,每个阶段只回答一个简单的问题:

  • 难不难? 让弱模型跑几遍,看它能不能做对。
  • 题目本身成立吗? 让强模型当裁判,判断前提是否自洽、答案是否唯一。
  • 有没有藏捷径? 把题目"挖掉一部分"再让模型做,看它是不是不靠完整信息也能答对。
  • 有问题的能不能救? 让强模型按"病因"重写,救不回来的就丢掉。

整体流程:决策树式分流

下面是一条样本从进入流水线到拿到最终标签的完整路径。粗体箭头是"留下来进训练池",普通箭头是"进修复车间":

输入:一批合成样本
B
让弱模型做 k 次
用同一道题让弱模型反复做 k 次(每次打乱选项),看它能答对几次
全做对(k/k)
→ 标 easy,送修复
部分对 / 全错
→ 进入下一阶段
C
让强模型当裁判,问"这题成立吗?"
把故事、问题、选项、标准答案都给强模型,判断题目本身有没有问题
不成立
→ 标 bad,送修复
成立
→ 继续分流
✓ 全错 + 可答
→ 标 hard,保留
部分对 + 可答
→ 进入下一阶段
D
挖掉部分内容,看模型还能答对吗?
三维探测:去故事 / 去问题 / 去选项,任一维度异常就判定有捷径
有捷径
→ 标 shortcut,送修复
✓ 无捷径
→ 标 medium,保留
E
自动修复:让强模型对症下药
把上面打了"修复"标签的样本(easy / bad / shortcut)送到强模型,按病因重写
修复完的样本 → 重新进入阶段 B,再走一遍分诊流程
如果几轮下来还是救不回来,就标 unfixable 丢弃

这个分流的核心是 "先做最便宜的检查,再做贵的" —— 弱模型跑 k 次也比一次强模型调用便宜,所以放在最前面;强模型只在真正需要它做精细判断的环节出场。

四个阶段在做什么

B
pass@k:让弱模型多跑几次,看难度
用同一道题让弱模型反复做 k 次(每次打乱选项)。如果它每次都对,这题对它就是太简单;如果它怎么做都做不对,这题对它就是真有挑战;部分对部分错就是中等难度。
用弱模型而不是强模型,是因为强模型能秒杀大部分题,反而看不出区分度。弱模型的失败模式才反映"这题有没有训练价值"。
关键产出:每条样本的 pass 次数 + 对应分桶
C
answerability:让强模型当裁判,看题目本身成不成立
把"故事 + 问题 + 选项 + 标准答案"都给强模型,问它一个问题:这题本身有没有问题?
如果前提互相矛盾、标注答案不唯一、或者根本没法从故事推出来,那就标 bad。这一步是过滤掉合成时的"翻车样本"。
注意:全做对的样本不需要做这一步 —— 既然弱模型都能做对,题目肯定是成立的。
关键产出:is_answerable + 不可答时的原因
D
三维 shortcut 探测:挖掉一部分,看模型还能不能答对
这是这个模块最有意思的设计。我们故意"残缺地"问模型 —— 把题目的一部分挖掉,如果模型还能答对,说明它根本没用到那部分信息,题目里就藏着捷径。
挖掉故事
只留问题和选项
还能答对 → 答案就藏在问题或选项的字面里
挖掉问题
只留故事和选项
还能答对 → 模型在靠故事词汇匹配选项
挖掉选项
让它直接生成答案
反而答错 → 原题靠的是排除法,不是真的理解
三个维度任意一个出现"异常",就判定有捷径
E
自动修复:让强模型对症下药
不是所有有问题的样本都直接扔掉,合成数据本来就贵,能救一个是一个。修复用的是"对症下药"的思路 —— 不同病因走不同的修复 prompt:
  • 太简单 → 让强模型把题目改难,加干扰、加多步推理
  • 有 bug → 修正前提矛盾或者答案歧义
  • 藏捷径 → 重写故事,让选项无法靠字面匹配
修复后的样本不是直接放行,而是 重新走一遍分诊流程。如果连续几轮都改不好,就标 unfixable 丢掉。
关键产出:repaired.parquet,作为下一轮的输入

每条样本最终会拿到一个标签

走完一轮分诊,每条样本都会被打上其中一个标签。绿色是"留下来",黄/橙/红是"需要处理":

hard ✓
题目成立,但弱模型做 k 次都没做对。这是训练价值最高的样本,优先保留。
medium ✓
题目成立,弱模型部分能做对,挖掉信息后做不对。中等难度但货真价实,保留。
easy
弱模型每次都做对,送去强模型加难度。
shortcut
藏着捷径,送去强模型重写故事或选项。
bad
题目本身有问题,送去强模型修逻辑或改标签。
unfixable
几轮修复都没救活,扔掉。

为什么强弱模型搭配着用

这个模块用了两个模型 —— 一个弱(便宜、快)、一个强(贵、准)。每个阶段为什么用哪个,都是有设计理由的:

阶段用什么模型为什么
阶段 B 测难度 弱模型 强模型几乎做啥都对,看不出题目难度。只有弱模型的失败才有信息量。
阶段 C 判可答 强模型 判断"题目逻辑自不自洽"需要深度理解,弱模型容易自己判错。
阶段 D 测捷径 弱模型 "捷径"指的是"不用真推理就能答对",所以要看的是弱模型在残缺信息下的表现。强模型即使没捷径也常能猜对,反而失真。
阶段 E 修题 强模型 修复要生成高质量新题,只有强模型扛得住。

迭代:让数据越来越干净

一轮分诊不是终点。修复后的样本要重新评估,因为修复也可能改坏。整个流程是一个螺旋上升的过程:

第 1 轮
评估原始数据 → 打标签 → 修复 → repaired_1.parquet
第 2 轮
只评估上一轮修复过的样本 → 打标签 → 修复 → repaired_2.parquet
...
继续迭代,直到达到 max_iter 上限
第 N 轮
最后一轮只评估、不修复,救不回来的标 unfixable
合并
把每一轮产出的 hard + medium 攒起来 → final/train_set.parquet

已经被标为 hard 或 medium 的样本不会重复评估 —— 它们直接进了"留用池",省掉无谓的算力。

这个模块在数据飞轮中的位置

filter 不是一个孤岛,它是 ToMEval 整个 数据飞轮 的下半场。上半场是 feedback(从模型错题中合成新题),下半场是 filter(把合成的新题筛干净):

feedback 从模型错题中
合成新训练数据
→
filter(本模块) 给新数据做体检,
留下能用的、修可以修的、扔不能用的

两个模块职责清晰:一个负责"造",一个负责"检",中间通过 synthetic.parquet 这个文件衔接。

怎么用起来

# 完整跑一遍:评估 + 修复迭代 + 合并最终训练集 python run_eval.py # 只跑评估和修复,不合并(可以用于调参) python run_eval.py --eval filter --dataset BigToM --max-iter 3 # 已经评估完了,只把 hard + medium 合并成最终训练集 python run_eval.py --eval finalize --dataset BigToM

运行完成后,产出会落在 filter_output/<数据集名>/ 目录下,包括每一轮的中间结果和最终的 final/train_set.parquet。
